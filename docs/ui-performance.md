# Inline SVG UI performance and embedded budget

Measurements are generated by `tools/build_ui.py` and verified by
`tools/build_ui.py --check`.

## Current interface budget

- Embedded production HTML: below the enforced 128 KiB limit.
- Local preview: same product/design plus preview-only simulation controls.
- External libraries: 0 B.
- Additional asset requests: 0.
- WebGL draw calls: 0.
- Product rendering: inline SVG.
- Live timeline: Canvas 2D, updated from 500 ms status samples.
- Browser history horizon: bounded to 30 minutes.

`product.svg` is a source-level maintainability boundary only. During generation it is
inlined before minification, then emitted to `ui/dist/dashboard.production.html` and
`include/web_assets.h`. The Pico therefore serves one flash-backed response through the
existing asynchronous, MSS-bounded raw-lwIP sender.

The product uses two small SVG shadow filters and one blurred contact shadow. Motion is
limited to the fan rotor, the subtle control-loop flow and component insertion. There are no
continuous particle systems, camera updates, shader passes or large external resources.

## Browser and responsive validation

Chrome DevTools Protocol captures use exact CSS device metrics at 1920×1080, 1440×900,
1366×768, 1024×768, 768×1024, 430×932 and 390×844. `tools/audit_ui_layout.py` checks
AUFBAU, REGELKREIS and LIVE at all seven sizes for visible collisions and horizontal
overflow. The final quality pass reports zero of both across all 21 combinations.

The product first frame is visible without JavaScript. Standard SVG, Canvas 2D, Fetch,
AbortController and requestAnimationFrame are used; no browser-specific rendering API is
required.
